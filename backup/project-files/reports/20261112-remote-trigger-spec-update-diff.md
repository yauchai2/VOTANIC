# Remote Trigger Implementation Spec 更新核對（2026-11-12）

規格頁最後編輯：2026-11-12 08:40（UTC）。頁面標示為 unverified。

## 一、整體判斷
規格已大幅改寫並精簡。11 月 9 日我記錄的技術細節（12 欄、行高 48、斷點 640、mobileOrder、widget 種類清單、128 個 widget 上限、唯讀與 readWrite、Phase 1 4.2 與 Phase 2 5.0 的分法）在現在的頁面中都已找不到。新版分為 Base Feature、Next Phase Feature、Feature Development 三層。我無法確認舊內容是被刪除，還是移到了其他頁面，需要同事確認。

## 二、新版規格的要點
- 編輯方式（Base）：以「清單檢視」為主，沿用舊設計；輸入有 3 類：Trigger Action（變成按鈕）、Instance Variable、Project Variable（變成變數控制項）；每個輸入有相關設定，並有選擇 Trigger 與變數的 UI。
- 版面：每個 layout 提供 2 種方向（直、橫），但一個 layout 只能選 1 種；固定格子大小，格子保持正方形，且不可小到難以觸控；每個場景 1 個 UI layout，不跨場景。
- 元件與設定：通用設定為 Size / Style。按鈕設 Color；數字輸入與數字滑桿設 Min、Max、Decimal；文字輸入設最大字數；核取方塊或開關無額外設定。元件基本尺寸只有 1x1 或 1x2。
- 日後可能加入：Label Text、帶上下按鈕的按鈕（Bool）、Color、Option box（選項）。
- 感應器（Base）：手機的陀螺儀、加速計、音量（麥克風）；同一時間只有 1 部手機控制感應器，並需要 UI 顯示目前的使用者。
- Web UI：顯示與 XRCC 相符的 UI；變數控制項在使用者沒有正在操作時才同步數據。
- Launcher：架設伺服器、可選用 Cloudflare Tunnel 公開連線、顯示 QR code、把連線資訊（localhost 埠）傳給 XRCC。
- 下一階段：在 XRCC 顯示網格並可拖放加入元件、layout 可跨場景、基本伺服器設定（埠號、QR 中央圖示）、偵測與控制裝置旋轉、更多元件設定。
- 再之後：自訂網頁 UI、無網格自由畫布。
- 另有「Include Test Plan」。

## 三、與現有設計的差異
| 項目 | 現有設計 | 新規格 | 建議 |
|---|---|---|---|
| 編輯器形式 | Stream Deck 式網格，可拖放、可縮放 | Base 為清單檢視，網格拖放屬下一階段 | 保留網格作為「下一階段」概念稿；另做 Base 版清單編輯器 |
| 格子 | 4 欄，可自由調整多種尺寸 | 固定、正方形格，只有 1x1 與 1x2 | 縮減為 1x1 與 1x2，格子保持正方形 |
| 方向 | 直向自動堆疊，橫向網格，另有 Phone order | 每個 layout 只選一種方向 | 改為 layout 的「Portrait / Landscape」單選；移除自動切換與 Phone order |
| Vector3 輸入與滑桿 | 已有 | 沒有 | 標為「規格外」，可保留在概念稿 |
| 唯讀（read only） | 已有 | 沒有 | 同上 |
| 數字元件設定 | 無 Min / Max / Decimal | 要有 | 設定面板加入三項 |
| 文字輸入 | 沒有 | 要有，設最大字數 | 新增 Text input |
| 場景 | 一個 deck 對應整個專案 | 每個場景一個 layout | 編輯器加入場景選擇，手機端顯示當前場景 |

## 四、風險與待確認
1. 「Base 用清單、網格屬下一階段」與 10 月 30 日會議「UI 編輯器可能做不完」一致，因此建議以清單編輯器為 Base 版。
2. 方向「只選一種」的規則沒有說明預設值、切換時網格如何轉換，需同事確認。
3. 「格子保持正方形」與「手機寬度不同」之間如何取得足夠大的觸控尺寸，規格沒有給數字（例如 56px 或 64px 下限）。
4. 感應器屬 Base，但目前沒有任何設計；隱私授權（iOS 需要 HTTPS 才能取得感應器）可能與 quick tunnel 或區域網路 http 衝突，需要確認。
5. 規格沒有說明唯讀、錯誤狀態、綁定缺失警告，這些是我自己加的，是否保留要由你決定。

## 五、建議的設計調整（尚未動 Figma）
1. 優先：把 Base 版編輯器重做為清單檢視，每列一個輸入，右側設定面板（Size、Color 或 Min/Max/Decimal、Max characters）。
2. 手機端：每個 layout 固定一種方向，格子為 1x1 與 1x2 的正方形格。
3. 補上 Text input 與感應器流程。
4. 場景選擇與「一個場景一個 layout」。
5. 現有網格編輯器移到「下一階段」分區，不刪除。
